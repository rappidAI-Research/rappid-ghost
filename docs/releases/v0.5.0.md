# Ghost v0.5.0

Ghost adds practical agent/service integration while keeping deterministic Docker
boundaries. See the [engineering audit](../release-audit-v0.5.md) for qualification
status and the [integration guide](../integrations.md) for runnable setup.

- Closed Node.js 24.22.3 environment and relative source adapter, without package installers.
- Official pinned native Codex 0.169.0 noninteractive adapter, one prompt/stdin, temporary guest-only state and a fixed model broker. Native tool-loop tests use a deterministic Responses fixture; hosted-account inference is not certified.
- Session-private Unix model/read-tool broker with exact HTTPS identity, host-only scoped credentials, strict input/resource grants, expiry/replay/rate/size limits, containment and durable minimal audit.
- Actual local llama.cpp/SmolLM2 CPU inference demo, with no direct agent access to the private model service or internet.
- Restricted MCP 2026-07-28 discovery/list/read-call subset, independently checked using official Go SDK 1.8.0, including a real guest client.
- Synthetic application-owned employee/tenant authorization and revocation example.
- Explicit `ghost init --integration ...` templates, Doctor JSON schema 3, sensitive-enterprise constraints and visible model/tool denial summaries.
- 27 GhostBench scenarios, expanded Docker/adversarial/crash/parallel tests and resource measurements. Existing 26 properties remain required.

Upgrade: existing v0.4 policy keeps its default behavior; integrations/broker grants
are opt-in. Init never overwrites policy. Broker sessions require network deny;
restricted profiles forbid service communication. No arbitrary images, dependency
installer, host fallback, broad private-network access or full MCP proxy is added.

Qualified platform: native Linux amd64 Docker Engine. Arm64 artifacts are
cross-built only; macOS/Desktop/Windows/WSL/rootless remain unqualified. Claude,
framework/dependency bundles and Ollama/vLLM-specific adapters are deferred.

Ghost supplies isolation and a capability ceiling. Applications still own user
and tenant authorization, read semantics, retention, output review and compliance.
Neither model quality nor complete security is promised.
