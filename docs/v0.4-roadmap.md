# v0.4 scope and next milestone

The implementation evolves the existing Docker/session/policy pipeline; no replacement runtime or parallel enforcement engine was introduced.

Delivered: descriptor-safe advisory diagnosis; closed reviewed runtime catalog; explicit standard-library Python adapter; restrictive validation profiles; Docker privilege checks; bounded configuration/approval artifacts; production-path Python CLI/bench tests; compatibility/configuration/audit documentation.

The v0.3.1 work on main was never published separately and is included in this release line. PR #16 is the continued integration branch, not an additional competing implementation.

Deferred to v0.5: a credential-owning tool/model broker with application authorization binding; a separately qualified Node environment and authentic Claude/Codex workflow; disk/evidence quotas and aggregate admission control; more platform qualification; supply-chain signatures/SBOM and independent security review. The [tool gateway contract](tool-gateway-design.md) specifies trust boundaries and acceptance tests. These are not v0.4 capabilities.

No project-detection result changes runtime selection, network permissions, host mounts, credentials or deterministic enforcement.
